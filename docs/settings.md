# 設定変更UI

router-uiの設定変更画面は、CLIコマンドを直接入力する代わりに、項目ごとのフォームから機種に対応したコマンドを生成します。

## 操作フロー

1. フォームへ設定値を入力する
2. router-uiが生成したコマンドを確認する
3. 確認ダイアログを経て、実行中の設定へ適用する
4. コマンド応答と`show config`の実行前後差分を確認する
5. 必要な場合だけ、別の確認操作で`save`を実行する

プレビューではルーターへコマンドを送信しません。適用時も`save`は自動実行しないため、適用結果を確認する前に起動設定が上書きされることはありません。

YAMAHA RTXの設定変更には管理ユーザー権限が必要です。一般ユーザー権限のセッションでは、機器からのエラーを表示し、起動設定への保存操作を出しません。

日付、時刻、NTP同期など、`show config`に設定行が残らない操作では実行前後差分が表示されない場合があります。各コマンドの応答もあわせて確認してください。

## 現在変更できる項目

### YAMAHA RTX

- 時刻
  - タイムゾーン
  - 日付と時刻
  - NTP送信元IPv4アドレス
  - NTPサーバーとの手動同期
  - NTP同期結果のSYSLOG記録
- 設定ファイル読込
  - PC上の設定ファイルをSSH/SFTPでRTFSへ一時転送
  - `load file`による差分更新または置換更新
  - 120〜3600秒の自動ロールバック
  - 読込後の`confirm`または`save`による明示的な確定
  - 一時ファイルの削除
- インターフェースIP
  - 固定IPv4・IPv6アドレス
  - DHCP・DHCPv6・RAによるアドレス生成
  - IPv4・IPv6アドレス設定の削除
- LAN動作モード
  - 速度と二重化方式
  - LAN1の物理ポート指定
  - MTU
  - LAN分割
- ルーティング
  - IPv4静的経路の追加・更新・削除
  - IPv4、DHCP、PP、トンネル、NULLゲートウェイ
  - メトリックと`hide`
- NAT
  - NATディスクリプターの動作タイプ
  - 外側・内側アドレス
  - LANインターフェースへの適用
- DNS
  - DNSサーバーIPv4アドレス
  - プライベートアドレスPTR問い合わせの処理
- DHCP
  - サーバー・リレー・無効
  - DHCPスコープとリース期間
- ログ・SYSLOG
  - IPv4・IPv6アドレスまたはホスト名の転送先（最大4件）
  - INFO・NOTICE・DEBUGログの出力
  - `user`・`local0`〜`local7`のfacility
  - YAMAHA従来形式、RFC 3164、RFC 5424
  - SYSLOG送信元IPv4・IPv6アドレス
- SNMP
  - SNMPv1の読み取り専用アクセス元
  - SNMPv1 Trapの送信先
  - `sysName`・`sysLocation`・`sysContact`
  - コミュニティ名のプレビュー・設定差分での伏せ字
- UPnP
  - UPnPの有効・無効
  - 外側アドレスの参照先
  - ポートマッピングの消去条件とタイマー
  - UPnPのDEBUGログ
- IPフィルター
  - IPv4静的フィルターの定義・削除
  - LANインターフェースへの適用・解除
- URLフィルター
  - HTTP URLフィルターの定義・削除
  - LANインターフェースへの適用・解除
- プロバイダー接続
  - PPPoE接続、PAP・CHAP認証
  - MRU、常時接続、NATディスクリプター
  - PP接続の無効化
- VPN
  - 事前共有鍵を使用するIPsecサイト間トンネル
  - SAポリシー、対向ゲートウェイ、暗号・認証アルゴリズム
  - トンネルの無効化

プロバイダー接続のパスワードとVPNの事前共有鍵はプレビューで伏せ字にし、ブラウザーへ再送しません。生成済みコマンドはサーバーのメモリーに最大10分間だけ保持され、適用時に一度だけ使用できます。`show config`の差分に認証情報が含まれる場合も伏せ字にします。

設定ファイルの内容もブラウザーのプレビューへ再表示しません。ファイル名、サイズ、行数、SHA-256、更新方法と実行予定の`load`コマンドだけを表示します。

## 現在の制限

- プロバイダー接続画面はPPPoE接続を対象とします。IPoE、MAP-E、DS-Liteなどは今後追加します。
- VPN画面は基本的な事前共有鍵方式のIPsecサイト間接続を対象とします。リモートアクセスVPNやIKE詳細設定は今後追加します。
- URLフィルターはYAMAHAの`url filter`が対象とするHTTP通信向けです。HTTPSのURL内容を一般的に検査する機能ではありません。
- SNMP画面はSNMPv1の読み取り専用アクセスとTrapを対象とします。読み書き可能なコミュニティとSNMPv3はまだ対象外です。
- UPnPを有効にするとLAN内の機器がポートマッピングを作成できます。信頼できるネットワークだけで使用してください。
- DEBUG SYSLOGは大量のログを発生させるため、調査後は無効へ戻してください。
- フィルターをインターフェースへ適用すると、どのフィルターにも一致しないパケットは破棄されます。許可ルールの不足に注意してください。
- RTX1210ではNATのhairpinオプションを使用できないため、画面に表示しません。
- ファームウェアリビジョンによって使用可能なオプションが異なる場合があります。
- 設定ファイル読込にはSSH接続に加えて、接続ユーザーと接続元に対するSFTP許可が必要です。Telnet接続では使用できません。
- `load`は暗号化された設定ファイルに対応していません。
- RTX1210の`load`はRev.14.01.26以降、`no-key-generate`はRev.14.01.28以降が対象です。

インターフェースIPや経路を変更すると、router-ui自身の管理接続が切断される可能性があります。これらの画面には、変更対象が現在の管理経路かどうかの警告、復旧手順の表示、将来的には確認待ちの自動ロールバックを追加します。

## 実機試験のルール

- 稼働中のルーターに対して、自動テストや反復プローブから設定変更コマンドを送信しない
- 設定変更の実機試験には、通信サービスへ接続されていない検証専用機を使用する
- 読み取りコマンドを含め、接続先と実行内容を確認してから試験する
- `save`、再起動、インターフェースIP、経路、NAT、フィルター、VPNの変更は特に慎重に扱う

通常の開発確認は、入力検証の単体テスト、モックトランスポート、型検査、ビルドで行います。
